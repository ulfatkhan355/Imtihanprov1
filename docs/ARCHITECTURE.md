# Imtihan Pro — Platform Architecture

## 1. Repository Structure
- `android/` — Native Android student application written in Kotlin, Jetpack Compose, Material 3, Navigation Compose, MVVM, Coroutines/Flow, Room v4 (`ImtihanDatabase`, 18 entities + `MIGRATION_3_4`), DataStore (`UserPreferencesDataStore`), WorkManager (`ImtihanSyncWorker`), OkHttp REST/PDF client with SHA-256 verification (`ImtihanApiClient`), native `PdfRenderer`, and pure JVM engines (`Stage3To8Engines.kt`). *(Requires JDK 17 + Android SDK 35 + Gradle 8.9 on Ubuntu to compile APK & run JVM unit tests.)*
- `admin/` — Responsive web Admin Console built with React 19, TypeScript, Vite, and Tailwind CSS v4 (mounted by `/src/main.tsx`), backed by `CloudflareAdminApiClient` (with explicit Offline UI Preview toggle preserving mock preview data) and `super_admin` RBAC user management.
- `backend/` — Cloudflare Worker API (`imtihan-pro-api`) with D1 SQL migrations/seed (`0001`–`0006`), Web Crypto PBKDF2 + HMAC-SHA256 sessions, D1 rate limiting, server-side exam key stripping & grading (`exam_sessions`), AWS SigV4 Backblaze B2 S3 integration, server-side Gemini AI Tutor handler (`gemini-4-hydrogen`), and Google Sign-In ID token verification with progress merge.
- `shared-contracts/` — Canonical Stage 2–8 & v1.0 API contracts and deterministic rules (`types.ts`, `endpoints.ts`, `rules.ts`) shared across `backend/`, `admin/`, and mirrored in Kotlin (`Stage3To8Engines.kt`).
- `scripts/` — Ubuntu setup (`setup-local.sh`), Worker deploy (`deploy-backend.sh`), Admin build (`build-admin.sh`), and Android Debug APK build (`build-android-debug.sh`).
- `tests/` — Automated Node.js TypeScript unit & integration tests (`node:test` + `node:sqlite`) verifying domain rules, SQLite/D1 migrations (`0001`–`0006`), Worker routes, Backblaze B2 SigV4 signing/upload/download/delete, Class 11 KPK catalog & search, server-side exam grading, SM-2/readiness/streak rules, AI Tutor gating, and feedback triage.
- `docs/` & `README_DEPLOYMENT.md` — Architecture, capacity modeling, and Ubuntu 26.04 deployment instructions.

## 2. Cloudflare + Backblaze B2 Infrastructure Architecture
- **API Compute**: Cloudflare Worker — `imtihan-pro-api` (`backend/wrangler.toml`, awaiting user deployment from Ubuntu).
- **Relational Database**: Cloudflare D1 — `imtihan-pro-db` (`b02fce90-8596-49e0-a79b-6ae3a427fff0`). Stores boards, KPK BISE sub-boards, classes (Class 11 `is_public_available = 1` for v1.0 launch; Classes 9, 10, 12 prepared without being publicly advertised), study groups, subjects, chapters, versioned content blocks with provenance fields, MCQs, server-side `exam_sessions`, exam patterns, past papers, PDF assets (`past_paper`, `textbook`, `notes_pack`, `syllabus`), student profiles, quiz submissions, bookmarks, mistakes, flashcards/SM-2 reviews, study tasks/activity days, achievements, feedback reports, admin accounts, AI ingestion queue, audit log, rate limits, and app/ad settings.
- **Object Storage**: Backblaze B2 — bucket `imtihan-pro-assets` (`1bdf9ec6cd50dbdfad180110`, endpoint: `https://s3.eu-central-003.backblazeb2.com`, region: `eu-central-003`). Uses provider-neutral `objectKey` in API contracts. Zero Cloudflare R2 usage.
- **Zero Client Secrets**: Android and Admin Console never embed B2 keys, signing secrets, or `GEMINI_API_KEY`. PDF uploads stream multipart form data to `/v1/admin/pdfs` where the Worker verifies `%PDF-` magic bytes and executes AWS SigV4 PUT requests to Backblaze B2; AI Tutor queries route exclusively through `POST /v1/tutor/ask`.

## 3. Product Scope & Visual Identity — Class 11 KPK Launch & Minimalist UI
- **Initial Launch Focus**: First-time setup defaults to **KPK Board** (`PESHAWAR` + all 8 KPK BISE sub-boards), **Class 11 (HSSC-I)** across `PRE_MEDICAL`, `PRE_ENGINEERING`, `ICS`, `FA`, and `ICOM`, and **English / Urdu** medium preference. Classes 9, 10, and 12 and inactive boards remain structurally supported in schema without being advertised in the student launch UI.
- **Visual System**: Clean Obsidian Dark (`#0A0F1A`, `#131B2B`) and Crisp Alabaster Light (`#F8FAFC`, `#FFFFFF`) canvases with subtle `0.8dp` hairline borders (`#28354D` dark / `#E2E8F0` light) for zero-distraction study focus.
- **5 Primary Android Navigation Tabs**: `Home`, `Learn`, `Practice`, `Resources`, `Profile`, opening secondary routes (`QuizSession`, `QuizResults`, `SmartInsights`, `MistakeMaster`, `BookmarksFlashcards`, `QuizHistory`, `AiTutor`, `StudyPlanner`, `FocusTimer`, `Motivation`, `Feedback`, `PdfReader`, `Downloads`).

## 4. Deterministic Rules, Integrity & Guardrails
- **Server-Side Exam Key Protection**: `POST /v1/exams/start` persists `exam_sessions` in D1 and strips `correctOptionId` and `explanation`; `POST /v1/quizzes/submissions` performs authoritative server-side grading and returns `perQuestionFeedback`.
- **Honest Readiness & Weak-Area Analytics**: `computeHonestExamReadiness` returns `null` when a student has fewer than `2` quiz attempts rather than fabricating readiness scores; `detectWeakChapters` flags low-accuracy chapters (`< 70%`) or unresolved mistakes.
- **Negative Marking & Grading**: `gradeQuizWithRules` calculates raw correct/incorrect/unanswered, optional negative marking (e.g., `-0.25`), pass threshold (`40%`), XP earned, and topic-wise accuracy breakdown.
- **SM-2 Spaced Repetition**: `calculateSm2NextReview` schedules flashcard intervals (`1` -> `6` -> `interval * easiness`) across Again/Hard/Good/Easy recalls.
- **Ethical Non-Intrusive Ads**: `shouldDisplayAd` strictly suppresses ads (`false`) during **Notes Reader**, **Solved Questions**, **MCQ Practice / Mock Exams**, and **PDF Reader**, as well as when daily frequency caps (`<= 3/day`) or runtime flags disable ads.
- **Privacy-Safe Leaderboard**: Opt-in only (`leaderboardOptIn`), displaying anonymized handles (`anonymizeLeaderboardHandle`) and never exposing emails or device IDs.
- **Honest AI Tutor**: Grounded strictly against chapter/subject D1 blocks via Gemini (`gemini-4-hydrogen`); returns HTTP `503 TUTOR_UNAVAILABLE` cleanly when `GEMINI_API_KEY` is unconfigured or offline.
